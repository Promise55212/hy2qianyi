# HY2 迁移真实机器验收

日期：2026-11-17（北京时间）。仅发布脱敏结论，不提交快照、真实地址、密码、TLS/WG 私钥或原始日志。

## 范围

hy2qianyi 是 qianyi 的 HY2 迁移版本。迁移程序从 root 私有 `/run/hy2qianyi.XXXXXXXX` 目录临时运行；成功后没有常驻迁移服务、定时任务或迁移脚本。迁入的节点、业务配置与统计属于迁移结果，继续由原 hy2jieshu 管理。

测试目标为用户授权可破坏性测试的全新 Debian 13.5 amd64 VPS，Python 3.13.5、官方 Hysteria v2.14.0。源为运行中的生产 HY2 VPS；另有共享 NAT 出口机。生产源业务全程未停止/重启，未改生产节点配置。源端仅运行临时只读快照导出及独立验收客户端；导出不主动采集或改写每日历史。

目标的同域 TLS 证书和主节点先作为测试环境准备完成。WG 使用目标新生成的独立密钥；共享 NAT 机仅临时增加一个运行期 Peer，先注册独立超时清理 timer，不修改其持久配置，不 restart WG。迁移程序自身不部署或迁移 WG。

- 20/20 节点用官方 Linux Hysteria 客户端完成正式 TLS 连接、预期出口检查与 UDP DNS；9 个普通节点（含主节点）走目标公网出口，11 个 NAT 节点走共享 NAT 出口。
- 9 个普通节点均完成 512 KiB POST SHA 回显；主节点和普通代表节点完成 512 KiB 下载 SHA 校验。
- 4 个 NAT 代表节点完成 193139 字节固定提交文件的下载 SHA 和 64 KiB 纯文本上传逐字节回显。其余 NAT 节点未重复大文件测试。
- 在真实落盘与停止服务后注入 start 调用失败，主节点及普通/NAT 两个临时节点的配置、密码、默认值和订阅自动恢复；配额总额及已用量接续，20 个服务恢复 active。
- 故意把已通过预检的目标临时配置损坏为无效 YAML，实际 Hysteria 启动失败，程序自动恢复旧目标；20 个服务恢复 active。
- 正常再次替换主节点及两个临时节点，其余 17 个目标独有节点保留。
- 使用真实 nftables 迁入 IPv4 /24 和 IPv6 /64 黑名单，保留目标独有端口的暂停和黑名单；启动故障时恢复原手工防火墙状态，随后成功迁入。失败与成功后均检查恢复文件、防护表和 drop-in 收尾。
- 实际重启测试 VPS 后，20 个节点自动恢复 active，配置、密码、到期元数据 SHA 一致，配额未回退、每日历史保留，迁移恢复文件、防护表、drop-in、preserve 标记均不存在。启动初期部分 NAT 节点因尚无握手被原生 preflight 安全拒绝，握手恢复后由原生 watchdog 自动恢复，未放宽保护条件。
- 最终版本 Linux 43 项自动化全部通过，无跳过；Windows PowerShell 转发和发布校验通过。

## 修复及测试条件

真实黑名单组合验收发现：内存计划中的 tuple 未转为 JSON 风格 list，首次 apply 预检拒绝。恢复材料经 JSON 序列化已是 list，手动 recover 正常。已修复计划生成格式，增加直接使用内存计划的回归，并重新通过真实故障回滚和成功迁入；首次失败不计为通过。

另修复目标旧节点事务期间自然到期时的 StopPost 锁等待边界：整个目标事务持有原生 preserve 标记，改写前有界等待既有 cleanup 退出，finally 清理标记。相关自动化覆盖 marker 生命周期、异常、存活外部 PID、过期 PID 和嵌套 stop。

Windows 经本地 TUN 到测试机的 QUIC 握手超时，因此外部节点连通验收从生产 VPS 启动独立客户端完成；Windows PowerShell 本身的二进制中转、参数引用、源端失败阻断和发布 hash 检查另外在 Windows 实际通过。

测试 HTTP echo 服务首次刷新测试载荷后未重启，造成 GET 参考 SHA 不一致；重启专用 echo 后代表普通节点重新通过。NAT 请求回到同一 HY2 入口的 echo 出现回流路径超时；改用第三方固定版本下载与回显后通过，未修改 MTU 或生产路由。没有将这些失败场景算作通过。

## 验证边界

尚未实际覆盖：全局 IPv6 入站、真实 CA 自动续期、长期运行与自然月重置、异常断电、跨发行版/不同管理库迁移，以及 VPS 直接 SSH 转发入口的完整跨机交互。默认 SSH 二进制导出/导入已跨真实机器执行；TLS/token/hash 和转发形态由真实回环 TLS 自动化覆盖。

TLS 私钥与 ACME 账户不在迁移包内，目标必须预先准备同域有效正式证书和续期配置。独立 portbw、暂停策略、自定义 unit、未知端口占用会拒绝，不会自动接管这些组件。迁移工具不负责 DNS 切换、旧机重装或 NAT 出口机管理。
